# Κομμωτήριο — Τοπικό App καταγραφής

Εφαρμογή καταγραφής ημέρας κομμωτηρίου για iPhone. Ο Νότης καταχωρεί από το
κινητό (κουμπιά, όχι Excel), η Λυδία παίρνει τα δεδομένα για ανάλυση.

## Αρχές (κλειδωμένες)

- **Τοπικά δεδομένα.** Τίποτα δεν ανεβαίνει σε server. Όλα ζουν στη συσκευή
  (IndexedDB). Τα οικονομικά στοιχεία δεν φεύγουν από το κινητό.
- **iPhone-first PWA.** Τρέχει στο Safari, μπαίνει στην αρχική οθόνη, δουλεύει
  offline. Μεγάλα κουμπιά, καμία επαφή με περιβάλλον Excel.
- **Εξαγωγή για Excel.** Παράγει CSV που ανοίγει καθαρά στο Excel και μπαίνει
  στο Συγκεντρωτικό με επικόλληση. Αποστολή σαν συνημμένο (Viber/Mail) από iPhone.
- **Σοβαρά αποτελέσματα.** Ο σκοπός δεν είναι η καταγραφή αλλά η πληροφορία:
  τζίρος/έξοδα/κέρδος ανά μήνα & υπάλληλο, συχνότητα πελατών.

## Τι καταγράφεται

- Πελάτης + εργασίες (τιμές από τιμοκατάλογο + ad-hoc ποσό) + υπάλληλος
- POS (σύνολο + ανάλυση καρτών)
- Έξοδα ημέρας (περιγραφή + ποσό)
- Μεταπώληση / προϊόντα (ποσό)
- ΦΠΑ ημέρας
- Ολοκλήρωση/κλείδωμα ημέρας

## Δεδομένα από το υπάρχον xls (έτοιμα)

`docs/data/seed.json` (δημόσιο):
- **13 κατηγορίες εργασιών** με τις τιμές τους (από τον Τιμοκατάλογο)
- **3 υπάλληλοι**: Νότης, Αγγελική, Μέλανι

**Πελατολόγιο (257 ονόματα): ΔΕΝ υπάρχει στο repo.** Φορτώνεται μία φορά σε κάθε
συσκευή από αρχείο, μέσα από την εφαρμογή (⚙︎ → Εισαγωγή). Το repo είναι δημόσιο,
οπότε κανένα προσωπικό στοιχείο δεν μπαίνει ποτέ εδώ.

Κωδικοί εργασιών (υπόμνημα χαρτιού): ακ, γκ, πκ, φ, χ, β, α, πκ, π, θ, λ, ι

## Prototype

Το πρώτο λειτουργικό prototype (artifact) υπάρχει ήδη και καλύπτει την
καταγραφή ημέρας με localStorage. Το project εδώ το ανεβάζει σε κανονικό
PWA με IndexedDB και εξαγωγή αρχείου.

## Δομή (v1.5)

```
docs/
  index.html             η μία σελίδα (καρτέλες: Πελάτες · Έξοδα · Ταμείο)
  manifest.webmanifest   όνομα/εικονίδιο για την αρχική οθόνη
  sw.js                  offline αντίγραφο της εφαρμογής (ανέβασε VERSION σε κάθε αλλαγή!)
  css/app.css            εμφάνιση (μεγάλα κουμπιά, safe areas, σκοτεινό θέμα)
  js/db.js               IndexedDB
  js/seed.js             πρώτο γέμισμα από data/seed.json (μία φορά μόνο)
  js/app.js              οθόνες και λογική
  data/seed.json         τιμοκατάλογος, πελάτες, υπάλληλοι
  icons/                 εικονίδια
```

Χωρίς build και χωρίς εξαρτήσεις. Τοπική δοκιμή: `cd docs && python3 -m http.server 8000`.
Για iPhone χρειάζεται https (π.χ. GitHub Pages με φάκελο `docs/`).

### Βάση δεδομένων (IndexedDB `salon`)

Όλα τα ποσά σε **λεπτά** (ακέραιοι).

| store | κλειδί | περιεχόμενο |
|---|---|---|
| `categories` | name | `prices` (λεπτά), `order` |
| `clients` | id | `name` (μοναδικό), `source` seed/app |
| `staff` | name | `order`, `active` |
| `visits` | id, index `date` | `date, client, staff, items[{cat, amount, note}], total` |
| `expenses` | id, index `date` | `date, desc, amount` |
| `days` | date | `posTotal, posCards{visa,mastercard,other}, retail, vat, locked, lockedAt` |
| `meta` | key | `seedVersion`, `seededAt` |

### Αποφάσεις / σημειώσεις

- Πελατολόγιο: 264 γραμμές → **257 μοναδικοί** (7 διπλά αφαιρέθηκαν, κενά καθαρίστηκαν). Εισάγεται τοπικά, όχι από το repo.
  Νέα ονόματα από την εφαρμογή μπαίνουν αυτόματα στο πελατολόγιο.
- Ad-hoc ποσό: κάθε εργασία δέχεται και «Άλλο ποσό» εκτός τιμοκαταλόγου· υπάρχει και εργασία «Άλλο» με περιγραφή.
- Ανάλυση καρτών POS: Visa / Mastercard / Άλλες, με προειδοποίηση αν δεν συμφωνούν με το σύνολο.
- Κλειστή ημέρα: δεν αλλάζει τίποτα χωρίς «Ξεκλείδωμα» από το Ταμείο.
- Μόνιμη αποθήκευση: ζητείται `navigator.storage.persist()`· η κατάσταση φαίνεται στο ⚙︎.
  Στο iPhone η πραγματική προστασία είναι η εγκατάσταση στην αρχική οθόνη (εμφανίζεται προτροπή).
- Κωδικοί εργασιών (12 για 13 κατηγορίες, διπλό «πκ»): εκκρεμεί, όταν χρειαστούν.
